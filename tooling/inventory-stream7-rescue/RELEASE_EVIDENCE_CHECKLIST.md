# Release Evidence Checklist

Use this checklist before any public release or significant update.

## Minimal evidence pack
- [ ] Commit the current state to git under your identity
- [ ] Generate a SHA256 manifest for the repository
- [ ] Keep the release zip locally with date/time in the filename
- [ ] Export one PDF or screenshot of the public-facing README/landing
- [ ] Preserve the final commit hash in release notes
- [ ] Keep one offline copy of the release zip and manifest

## Optional but recommended
- [ ] Tag the release in git
- [ ] Keep a signed or dated note describing the scope of the release
- [ ] Save GitHub screenshots after publication
- [ ] Keep a local copy of the generated reports demonstrating the repository behavior

## Rule
This is a minimum evidence layer. It is designed to help support authorship and official registration later, not to replace legal procedure.
